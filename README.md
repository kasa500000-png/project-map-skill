# Project Map v0.7

**코드 대신 기능을 선택하고, 변경의 영향을 확인하며 Codex와 개발하세요.**

[English](README.en.md) · [개선 기록](docs/four-phase-upgrade.md) · [설정](skills/project-map/references/config.md)

화면·기능 지도 → 자연어 요청 → Codex의 변경 계획 → 사용자 검토 → 코드 작업 → 실제 변경과 검증 확인.

## 기존 사용자: 먼저 업데이트와 기록 이전

기존 지도 서버와 Codex 작업을 중단하고, 복제한 스킬 저장소에서 실행합니다.

```bash
git pull --ff-only
node -p "require('./package.json').version"
```

`0.7.0`이 표시되어야 합니다. 복사 설치는 기존과 같은 설치 옵션으로 다시 설치하세요.
앱에 이전 `.project-map/tasks` 기록이 있으면 **그 앱마다 한 번** 아래 명령으로 옮깁니다.

```bash
node skills/project-map/scripts/project-map.mjs migrate-state --project "/실제/앱/경로"
```

새 기본 경로는 `.agents/project-map-state`입니다. 원본 `.project-map`는 삭제하지 않고,
이전의 승인 상태는 다시 검토하도록 초기화합니다. 실행 중인 작업·심볼릭 링크·이미
존재하는 대상 폴더가 있으면 자동 병합하지 않고 중단합니다. 기록을 확인하기 전에는
원본을 삭제하지 마세요. 처음 설치하거나 기록이 없는 앱에는 이전 명령이 필요 없습니다.

## 설치

Git, Node.js 20 이상, 로컬 앱 프로젝트를 열 수 있는 Codex가 필요합니다.

```bash
git clone https://github.com/kasa500000-png/project-map-skill.git
cd project-map-skill
node scripts/install.mjs
```

앱 프로젝트를 Codex에서 열고 요청하세요.

```text
$project-map 현재 프로젝트의 작업 지도를 열어줘.
내가 선택한 기능의 변경 계획을 먼저 보여주고, 확인 후 작업해줘.
```

기본 설치는 `~/.agents/skills/project-map`에 링크를 만듭니다. 기존의 다른
스킬을 덮어쓰지 않습니다. 특정 앱에만 설치하려면 `--project "/path/to/app"`,
링크가 불가능하면 `--copy`를 사용합니다. 복사 설치는 업데이트 후 다시 설치합니다.
다른 사람도 각자의 프로젝트에 동일하게 설치할 수 있습니다.

## 기능 단위로 이해하기

기본 작업실은 화면 하나와 관련 구현을 묶고, 여러 기능이 공유하는 코드를 별도로
표시합니다. 기능 하나에 여러 파일이 연결될 수 있으며 파일 하나도 여러 기능에서
사용될 수 있습니다. 기능 선택은 진입 파일을 지정하는 것이지 모든 연결 파일의
수정을 허용하는 것이 아닙니다.

지도에서 이름을 바꾸면 `project-map.config.json`에 저장됩니다. Codex에 요청해
`features` 설정으로 여러 파일을 업무 기능 하나로 묶을 수도 있습니다. 자세한
예제는 [개선 기록](docs/four-phase-upgrade.md)을 확인하세요.

화면 이동과 공통 구현 사용은 구분합니다. 연결선이 없다는 것은 영향이 없다는
보장이 아닙니다. 원본 파일 중심의 상세 화면과 영어 UI는 `/legacy`에 남겨 뒀습니다.

## 요청과 실제 실행은 다릅니다

기능을 누르고 변경 내용을 입력해 요청을 저장한 뒤, 제공된 요청문을 Codex에
전달합니다. Codex가 소스를 확인해 현재/예상 지도를 게시하면 사용자가 승인하거나
수정 의견을 남깁니다. 코드가 바뀌거나 계획이 수정되면 이전 승인을 재사용하지 않습니다.

기본 수동 모드에서는 저장·승인 버튼만으로 종료된 Codex 세션이 시작되지는 않습니다.
활성 세션이 기다리지 않는다면 복사한 요청문을 Codex 대화에 전달하세요.
수정 완료와 검증 통과를 구분하고, 확인하지 않은 결과는 미확인으로 표시합니다.

## 예제와 명령

```bash
npm run demo
node skills/project-map/scripts/project-map.mjs --help
npm run check
npm test
```

예제는 소스 분석용 가상 앱입니다. 실행 가능한 완성 Next.js 앱이 아닙니다.
지도 실행에는 npm 패키지, 별도 서버 계정, 데이터베이스나 API 키가 필요 없습니다.

## 업데이트 / 제거

```bash
git pull --ff-only
# 복사 설치에서만 재실행:
node scripts/install.mjs --copy
# 제거:
node scripts/install.mjs --uninstall
```

프로젝트 설치를 선택했다면 동일한 `--project` 경로를 사용하세요. 설치기의 제거는
사용자가 수정한 복사본을 삭제하지 않습니다. 원본 앱과 작업 기록도 지우지 않습니다.

## 범위와 개인정보

JS/TS와 React·Next.js·Expo 관례 중심의 정적 분석입니다. 동적 이동, 외부 서비스,
데이터베이스 규칙 등은 추가 확인이 필요합니다. 지도는 최신 코드 탐색을 돕는
인덱스이지 전체 동작의 증명이 아닙니다.

앱 저장소에서는 `.agents/project-map-state/`를 `.gitignore`에 추가하세요. 생성된 지도·요청은
로컬 정보이며 공개 저장소에 올리지 마세요. 서버는 루프백에서만 동작하고 원본
앱 코드를 자동 업로드하거나 분석 텔레메트리를 수집하지 않습니다. Codex에 보낸
코드·요청에는 사용하는 Codex 환경의 정책이 적용됩니다.

## 이번 4단계 개선

| 단계 | 사용할 수 있는 기능 |
| --- | --- |
| 1차 | 기능 단위 묶음, 이름 저장, 화면 이동·공통 코드 관계 설명 |
| 2차 | 실제 수정 파일 기준 영향 재계산, 지도 밖 파일 비교, 검증 명령·캡처 증거 |
| 3차 | 작업 전 체크포인트, 복원 미리보기, 동시 변경 보호, 중단·재개 검토 |
| 4차 | 동일 지도 재사용, 실제 작업 간 충돌 비교, 선택적 Codex 직접 연결 |

변경 없는 지도는 파일 해시 확인 후 재사용합니다. 파일이 바뀌면 전체 관계를 다시
계산하므로 **파일별 증분 파서가 구현된 것은 아닙니다.** 병렬 작업 비교도 충돌
후보를 보여주는 기능이며 여러 에이전트를 자동 실행하거나 병합하지 않습니다.

### 선택 사항: 지도에서 Codex에 직접 전달

로컬에 `codex` CLI가 설치되고 로그인되어 있어야 합니다. 직접 연결을 선택한 경우에만:

```bash
node skills/project-map/scripts/project-map.mjs serve --project "/path/to/my-app" --open --codex
```

실제 앱 경로를 지정하세요. 지도에서 계획 요청 → 계획 검토·승인 → 실행 요청을
별도로 진행합니다. 실행 상태를 확인하거나 현재 작업을 중단할 수 있습니다. 이 직접 연결은 권한 확대를 승인하지 않습니다.
기존 Codex 사용량·요금 조건이 적용됩니다. 자동 설치·로그인·API 키 저장은 하지 않습니다.
직접 연결은 **실험 기능**입니다. 설치된 CLI 통신 규격·로그인 상태를 점검하고 대화를 재개하지만, 모의 프로세스로 검증했으며 **실제 계정·모델과 Mac GUI 동작은 별도 확인이
필요합니다.** 호환되지 않으면 기존 요청문 복사 방식을 사용하세요.

### 검증과 복원에서 주의할 점

검증 명령의 종료 코드와 캡처를 등록해 볼 수 있지만 앱 실행·캡처를 자동 수행하지는
않습니다. 캡처가 있다는 이유만으로 기능을 통과 처리하지 않습니다. 체크포인트는
계획한 로컬 파일만 보존하며, 외부 데이터·결제·배포를 되돌리지 않습니다. 복원 전후
다른 작업을 멈추고, 충돌 또는 중간 실패 시 복구 기록을 확인하세요.

자세한 사용 조건은 [직접 연결 안내](skills/project-map/references/bridge.md),
구현 범위와 테스트 결과는 [검증 기록](docs/validation.md)을 확인하세요.


## v0.7 안정화에서 달라진 점

- 실제 실패 기록을 AI의 통과 설명으로 덮어쓰지 않습니다. 현재 코드·계획에 연결된
  실행 증거가 없는 통과 보고는 미확인입니다. 일반 빌드 통과는 모든 기능의 통과가 아닙니다.
- 전체 변경 비교와 복원용 최종 상태 기록이 끝난 뒤에만 완료됩니다. 마무리 실패는
  별도 상태로 표시하고 저장된 요청으로 재시도합니다.
- 동일 Git 작업 폴더에서는 수정 작업 한 건만 실행합니다. 여러 세션이나 다른 상태
  폴더에서도 중복 실행을 거부합니다. 외부 편집기까지 잠그는 것은 아닙니다.
- 변경 전 / 승인한 예상 / 실제 결과를 함께 유지합니다. 변경 표시와 미확인 검증을
  기능 지도에 전달하고, 콘텐츠 JSON·이미지·설정 파일도 승인·백업·복원할 수 있습니다.
- 작업 취소와 기록 보관, 페이지별 기록 조회, 저장 용량 확인을 제공합니다.
  취소는 파일 되돌리기가 아니며, 보관은 삭제가 아닙니다. 백업을 자동 삭제하지 않습니다.

앱 저장소에서는 `.agents/project-map-state/`, `.agents/project-map-control/`와
이전 `.project-map/`를 모두 무시하세요. `.agents` 아래의 정상 Codex 샌드박스 보호를
사용하지만 전체 권한 실행이나 다른 로컬 프로그램을 방어하는 보안 장치는 아닙니다.
권한 문제를 해결하려고 전체 샌드박스를 해제하지 마세요.
