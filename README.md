# Project Map

**개발할 부분을 지도에서 선택하고, 변경의 영향을 확인하며 Codex와 작업하는 스킬입니다.**

[English](README.en.md) · [스킬 지침](skills/project-map/SKILL.md) · [가상 예제](examples/sample-app)

Project Map은 프로젝트 코드를 읽어 화면의 이동 흐름과 공통 요소·데이터의 관계를 보여줍니다. 원하는 기능을 선택해 요청하면 Codex가 관련 코드를 확인하고 **어떤 화면이 어떻게 달라질지** 계획을 지도에 표시합니다. 사용자가 계획을 확인한 뒤 작업을 진행하고, 결과 지도에서 예상과 실제 변경을 비교하며 다음 요청을 이어갑니다.

## 핵심 흐름

1. **프로젝트 이해:** 스킬을 불러 현재 화면과 기능의 흐름을 확인합니다.
2. **작업 선택:** 화면·기능을 클릭해 원하는 결과를 설명합니다.
3. **변경 예상:** Codex가 연결된 기능을 검토하고 현재 지도와 변경 후 예상 지도를 보여줍니다.
4. **계획 확인과 실행:** 사용자가 계획을 승인하거나 수정 의견을 남기고, 승인된 계획으로 Codex가 작업합니다.
5. **결과 비교와 반복:** 실제 변경 지도와 기대한 결과의 확인 상태를 살펴본 뒤 같은 기능에서 다음 요청을 이어갑니다.

Node.js 표준 라이브러리로 실행합니다. 별도 데이터베이스, API 키, npm 패키지 설치가 필요하지 않습니다. 지도와 요청은 내 컴퓨터의 프로젝트 폴더에 저장됩니다.

## 먼저 알아둘 점

- **지도는 실제 소스를 분석합니다.** JavaScript·TypeScript의 정적 import와 React 계열 파일 구조를 중심으로 관계를 추정합니다.
- **요청 저장 후에는 계획을 먼저 보여줍니다.** Codex가 관련 소스를 읽고 계획을 작성하면 지도에서 검토할 수 있습니다. 일반 브라우저의 저장·승인 버튼이 종료된 Codex 세션을 자동 실행하지는 않습니다.
- **연결 종류를 구분합니다.** 화면 이동 화살표와 공통 코드 사용 관계를 따로 봅니다. 자동 추정, 누락, 수동 선언 관계도 근거와 함께 확인해야 합니다.
- **v0.2는 세션 자동 배정 도구가 아닙니다.** 병렬 후보와 조건을 보여주며, 여러 Codex 세션을 자동 생성·통합하는 기능은 포함하지 않습니다.

## 1. 맥에 설치하기

준비물은 **Git, Node.js 20 이상, 로컬 프로젝트에 접근할 수 있는 Codex**입니다.

터미널에서 다음 명령을 실행합니다.

```bash
git clone https://github.com/kasa500000-png/project-map-skill.git
cd project-map-skill
node scripts/install.mjs
```

설치기는 `~/.agents/skills/project-map`에 이 저장소의 스킬을 가리키는 링크를 만듭니다. 이미 다른 스킬이 같은 위치에 있다면 덮어쓰지 않습니다.

이후 **개발 중인 앱 프로젝트를 Codex에서 열고** 다음과 같이 요청합니다.

```text
$project-map 현재 프로젝트의 작업 지도를 열어줘.
```

스킬 목록이 갱신되지 않았다면 선택기를 다시 열거나 새 대화에서 확인합니다. 프로젝트 코드를 이 공개 저장소로 옮길 필요는 없습니다.

### 특정 프로젝트에만 설치

```bash
node scripts/install.mjs --project "/Users/your-name/Developer/my-app"
```

지정한 프로젝트의 `.agents/skills/project-map`에 설치합니다. 개인 설치와 프로젝트 설치 중 한 방식을 선택하면 됩니다. 생성된 링크는 내 컴퓨터의 절대 경로를 가리키므로 팀 공유용으로 그대로 커밋하지 마세요. 다른 사람도 각자 이 저장소에서 설치하면 됩니다.

### 링크를 만들 수 없는 환경

```bash
node scripts/install.mjs --copy
```

복사 설치에서는 업데이트 후 설치 명령을 다시 실행해야 합니다. 사용자가 설치된 파일을 수정했다면 설치기는 덮어쓰지 않고 중단합니다.

## 2. 지도에서 요청하기

1. **작업할 화면이나 기능을 선택합니다.** 처음에는 화면을 중심으로 보고, 필요할 때 연결된 파일을 확인합니다.
2. **원하는 변경을 적습니다.** 예: “작업 상세 화면에서 제목 입력을 가장 위로 올려줘.”
3. **변경 의도를 선택합니다.** 화면 표시, 동작, 공유 데이터 형식에 따라 확인할 범위가 달라집니다.
4. **예상 범위를 확인하고 요청을 저장합니다.** 요청에는 선택한 기능과 분석 시점의 정보가 함께 저장됩니다.
5. **Codex에 변경 계획 작성을 지시합니다.** 지도에서 제공하는 요청문을 복사하거나, 아래처럼 요청 ID를 전달합니다.

```text
$project-map 저장한 요청 <요청 ID>의 관련 코드를 확인하고, 변경 후 예상 지도를 먼저 보여줘.
```

지원되는 데스크톱 내장 브라우저에서는 선택 요소를 Codex 대화에 첨부하는 버튼을 사용할 수 있습니다. 기능 지원 여부를 실행 중 확인하며, 지원되지 않으면 복사 가능한 요청문을 제공합니다. 선택창이 열렸다는 사실과 요청이 실제 전송됐다는 사실도 구분합니다.

Codex가 활성 세션에서 요청을 기다리고 있다면 저장한 작업을 이어받을 수 있습니다. 종료된 세션은 저장 버튼만으로 다시 시작되지 않으므로 위 요청문을 Codex에 보내 주세요.

## 3. 지도에서 변경 계획 확인

Codex가 계획을 작성하면 **계획 검토** 화면에 현재 구조와 변경 후 예상 구조, 기능별 수정 내용·기대 결과·확인 방법이 나타납니다. 코드 수정은 아직 시작되지 않은 상태입니다.

- 기대한 방향이면 **이 계획으로 작업 진행**을 선택합니다.
- 범위나 결과가 다르면 **계획 수정 요청**에 의견을 남깁니다.
- 계획이 바뀌면 새 버전을 다시 확인합니다. 확인 이후 코드가 바뀌었을 때도 오래된 계획으로 실행하지 않도록 검사합니다.

승인 후 활성 Codex가 이어서 처리할 수 있습니다. 대화가 끝났다면 지도에서 제공하는 이어가기 요청문을 Codex에 보냅니다. 화면 표시만 바꾸는 요청은 연결선이 그대로일 수 있으며, 노드의 예상 결과 설명에서 차이를 확인합니다.

## 4. 작업 후 변경 지도 확인

Codex는 요청을 시작하기 전에 최신 소스와 계획 범위를 확인합니다. 작업을 마치면 해당 요청의 기준 시점과 현재 파일을 비교하고 결과를 기록합니다. 비교 대상은 분석에 포함된 소스 파일이며, 제외된 파일이나 지원하지 않는 형식은 Git 변경 내역에서도 별도로 확인해야 합니다.

| 표시 | 의미 |
| --- | --- |
| 수정 후보 | 요청을 구현하기 위해 변경할 가능성이 있는 파일 |
| 참고 | 기존 동작과 규칙을 이해하기 위해 읽을 영역 |
| 함께 확인 | 변경 이후 정상 동작을 확인할 영역 |
| 실제 변경 | 기준 시점 이후 생성·수정·삭제된 소스 파일 |
| 범위 밖 변경 | 예상 수정 범위에 포함되지 않았던 실제 변경 |

이미 수정되어 있던 파일도 요청 생성 후 내용이 바뀌지 않았다면 새 작업의 변경으로 계산하지 않습니다. 변경 비교는 파일 내용의 해시를 사용하므로 커밋하지 않은 변경도 확인할 수 있습니다. 같은 기간 다른 작업이 수정한 내용도 비교에 포함될 수 있으므로 원인을 함께 확인해야 합니다.

검증 상태는 실제로 기록된 결과를 따릅니다. 요청이 완료되었다는 이유만으로 테스트가 통과했다고 표시하지 않습니다. 파일이 바뀌었다는 사실과 기대한 동작이 확인됐다는 사실도 구분합니다. 기능에 연결된 검증 결과가 없으면 해당 기대 결과는 **미확인**으로 남습니다.

결과 화면에서 이어서 요청하면 이전 작업과 연결된 새 요청을 만들 수 있습니다. 완료된 기록을 덮어쓰지 않고 최신 소스를 기준으로 다시 계획합니다.

## 먼저 예제로 둘러보기

아직 실제 앱에 적용하기 전이라면 저장소의 작은 가상 프로젝트를 열 수 있습니다.

```bash
node skills/project-map/scripts/project-map.mjs serve --project examples/sample-app --open
```

예제에는 홈·목록·상세·리포트·설정 화면과 공통 데이터가 있습니다. 예제 앱 자체를 실행하거나 npm 패키지를 설치할 필요는 없습니다.

## 명령줄 사용

아래 명령은 저장소 루트에서 실행합니다. 경로에 공백이 있으면 따옴표로 감쌉니다.

```bash
# 지도 생성
node skills/project-map/scripts/project-map.mjs scan --project "/path/to/app"

# 로컬 작업 지도 열기
node skills/project-map/scripts/project-map.mjs serve --project "/path/to/app" --open

# 저장된 요청 확인
node skills/project-map/scripts/project-map.mjs tasks --project "/path/to/app"

# 환경 점검
node skills/project-map/scripts/project-map.mjs doctor --project "/path/to/app"
```

자세한 명령은 다음 도움말에서 확인합니다.

```bash
node skills/project-map/scripts/project-map.mjs --help
```

## 업데이트와 제거

처음 복제한 `project-map-skill` 폴더에서 업데이트합니다.

```bash
git pull --ff-only
```

기본 링크 설치는 저장소의 새 버전을 그대로 사용합니다. 복사 설치는 `node scripts/install.mjs --copy`를 다시 실행합니다. 설치 시 `--project`를 사용했다면 업데이트·제거에도 같은 프로젝트 경로를 전달합니다.

```bash
node scripts/install.mjs --uninstall
```

제거 명령은 이 설치기가 만든 링크나 변경되지 않은 복사본만 제거합니다. 사용자 수정이 있으면 보존하고 중단합니다. 앱 프로젝트의 지도와 요청 기록은 제거하지 않습니다.

## 분석 범위와 한계

- 우선 지원 대상은 JS/TS, React, Next.js·Expo 스타일의 화면 파일과 상대 경로·일부 경로 별칭의 정적 참조입니다. 인식 가능한 정적 링크와 라우터 호출에서 화면 이동 후보를 추출합니다. 다른 파일도 일부 표시될 수 있지만 언어별 완전한 의미 분석을 제공하지 않습니다.
- 동적 import 표현식, 문자열 기반 이벤트, 런타임 라우팅, 서버 밖의 데이터 규칙은 자동 분석에서 빠질 수 있습니다.
- 공통 요소를 함께 쓰는 기능은 파일이 달라도 조율이 필요할 수 있습니다. 병렬 후보는 조건부 안내이며 충돌 방지 보장이 아닙니다.
- 큰 파일·파일 개수 제한이나 분석에서 빠진 부분은 경고를 확인하세요. 오래된 지도를 사용하려고 하면 새로 분석하도록 안내합니다.
- 최초 지도 생성 이후에도 Codex는 작업에 필요한 최신 코드를 읽어야 합니다. 로컬 분석기가 프로젝트를 다시 스캔하는 것과 언어 모델에 모든 코드를 전달하는 것은 다릅니다. 토큰 또는 시간 절감률을 보장하지 않습니다.

기능 이름이나 추가 관계는 [설정 안내](skills/project-map/references/config.md)의 `project-map.config.json`으로 보완할 수 있습니다.

## 로컬 데이터

생성된 지도와 요청은 기본적으로 대상 프로젝트의 `.project-map/`에 저장됩니다. 이 폴더에는 파일 경로, 해시, 관계 정보, 작성한 요청 등이 포함됩니다. 앱 저장소의 `.gitignore`에 다음 줄을 추가하는 것을 권합니다.

```gitignore
.project-map/
```

도구는 `.env` 등 민감 파일, 심볼릭 링크, 의존 패키지와 생성 디렉터리를 분석에서 제외합니다. 원본 소스 본문을 지도 JSON에 복사하지 않습니다. 지도 서버는 루프백 주소에서 동작하고, 외부 업로드나 분석 텔레메트리는 포함하지 않습니다. Codex에 전달한 요청과 코드의 처리는 사용 중인 Codex 환경의 정책을 따릅니다.

## 개발 및 기여

실행 의존성은 없습니다. 테스트는 Node.js 기본 테스트 러너로 실행합니다.

```bash
npm test
npm run check
```

검증 범위와 브라우저 확인의 한계는 [검증 기록](docs/validation.md)에 정리했습니다.

문제를 제보할 때는 실제 API 키나 비공개 앱 코드를 포함하지 말고, 재현 가능한 작은 예제와 예상 동작을 공유해 주세요. 새 프레임워크를 지원할 때는 화면 탐지, 참조 분석, 변경 영향, 누락 경고를 함께 검증하는 테스트를 추가해 주세요.
