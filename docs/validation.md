# Validation record — v0.7 stabilization

## Node/API and protocol regression suites

The baseline v0.6 suite contained 108 tests. Commit 1 of this upgrade passed 120;
commit 2 passed 126. The final suite currently contains 141 tests. Run `npm test`
and inspect the actual result for the checked-out commit. `npm run check` validates
package files, version consistency and JavaScript syntax.

New regressions cover: failed receipts versus reported passes; stale/same-check
reruns; recoverable finalization; cross-process/worktree execution ownership;
explicit model disposition; transitive task conflicts; planned content and image
artifacts; three-way change flags; protected state migration; fail-closed installed
protocol/auth checks; thread resumption; uncertain process termination; history
pagination/cancellation/archival; and read-only storage metrics.

## Browser evidence

The shipped UI ran in real Chromium at 1440×1000 and 390×844 with offline fixture
responses generated by the actual Node workflow (`tests/browser_component.py`).
The test exercises feature selection, request save, plan review, three simultaneous
maps, result/evidence/safety displays and horizontal overflow. No app mockup was
substituted for the shipped HTML/CSS/JavaScript. The sample source app itself is
not run; an attached screenshot does not prove product behavior.

A live browser-to-localhost test is also provided (`tests/browser_e2e.py`), including
restore and archive over actual HTTP. The development browser rejected localhost
with `ERR_BLOCKED_BY_ADMINISTRATOR`; no restriction was bypassed. Local HTTP APIs
are independently exercised by Node tests. The CI workflow runs the live browser
test on its standard Linux runner. Configuring CI is not evidence of a pass: check
the reported workflow conclusion for the exact published commit.

## Remaining limits

No authenticated Codex binary/model was available in development. Direct adapter
tests use deterministic stdio processes and synthetic protocol schemas. Installed
CLI/account compatibility, live model output, real app behavior and the user's
Mac GUI require acceptance testing. Hosted macOS Node CI is not Mac GUI testing.
Large real-world codebases have not been load-tested; metadata-first polling and
pagination reduce work but no measured speed/token-saving percentage is claimed.

Checks use temporary synthetic projects. No user's application, external database,
production deployment, payments or account credentials were changed. Backups and
migration tests verify local behavior only; multi-file restore is not an atomic
filesystem transaction and external changes are not rolled back.
